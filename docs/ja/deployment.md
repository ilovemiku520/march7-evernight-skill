# QQ のデプロイ、管理者設定と権限

本説明はオプションの QQ アダプターに対応するもので、AstrBot 4.29.1 と NapCat 4.18.38 のローカル環境での組み合わせを参考にしています。上流プロジェクトのインストール手順に従ってください。バージョン変更後は画面のフィールドを確認してください。本リポジトリには QQ、NapCat、AstrBot のインストーラーは含まれず、他者のログイン設定も提供されません。

## デプロイ

1. [AstrBot 公式プロジェクト](https://github.com/AstrBotDevs/AstrBot) から AstrBot をインストールして起動します。[公式 Docker デプロイ](https://docs.astrbot.app/deploy/astrbot/docker.html) も参照できます。ログに従って管理画面のアカウントを設定してください。デフォルトの管理画面ポートは通常 6185 です。管理画面には、ローカルホストまたは信頼できるイントラネットからのみアクセスを許可してください。公開テンプレートには管理画面のパスワードは含まれていません。
2. [NapCat 公式プロジェクト](https://github.com/NapNeko/NapCatQQ) から NapCat をインストールし、起動ログに従って WebUI を開きます。通常のポートは 6099 です。ポートが競合する場合はログを優先してください。自身のデプロイ時に生成された WebUI トークンでログインし、その後、自身の QQ サブアカウントで QR コードをスキャンします。[公式の基本設定](https://doc.napneko.icu/config/basic) を参照してください。WebUI トークンと QQ セッションの資格情報は、いずれもデプロイ担当者のプライベート設定内にのみ保持してください。
3. [AstrBot 公式 OneBot v11 ガイド](https://docs.astrbot.app/platform/aiocqhttp.html) に従って新しい接続を作成し、NapCat で WebSocket クライアントを新規作成して、AstrBot のリバース WebSocket アドレスに接続します。例: 同じマシンでリッスンポートが 6199 の場合は `ws://127.0.0.1:6199/ws` を使用します。両端では同じ独立した接続トークンを使用します。WebUI トークンと接続トークンを混同しないでください。同じネットワーク上のコンテナでは、実際のサービス名を使用できます（例: `ws://astrbot:6199/ws`）。コンテナ内のループバックアドレスをそのまま使用することはできません。
4. リポジトリの `qq-adapter/plugin` の内容を、AstrBot のプラグインディレクトリにある `astrbot_plugin_march7_evernight` という名前のフォルダに配置し、`metadata.yaml`、`main.py`、設定スキーマ、およびリソースの相対位置を維持します。プラグインを再読み込みし、起動ログを確認してください。
5. AstrBot のモデルプロバイダー設定で OpenAI 互換インターフェースを選択し、自身の DeepSeek API キーを入力します。API エンドポイントとモデル名は、[DeepSeek 公式ドキュメント](https://api-docs.deepseek.com/) と自身のアカウントで確認してください。キーを人格プロンプトやリポジトリに書き込まないでください。まず管理画面のチャットでテストし、その後、自身の QQ のプライベートチャットまたはグループ内の @ でテストします。

## 管理者設定

1. AstrBot の「設定ファイル → アクセス制御 → 管理者 → 管理者 ID」で、自身の実際の QQ ユーザー ID を追加します。これは `admins_id` 設定に対応します。現在のバージョンの公式説明で画面を確認し、アカウントを公開人格ルールに書き込まないでください。
2. このプラグインの設定で、`owner_qq` に同じ QQ ID を入力します。公開デフォルト値は空です。空の値、無効な値、およびメッセージ本文でのみ自己申告されたアカウントは、いずれも認可されません。
3. キャラクター管理の権限は、デフォルトで実際の各メッセージごとに検証されます。最初に「私は管理者です」と言う必要はありません。三月なのかへの切り替え、長夜月への切り替え、昼夜スケジュールの復元を自然に要求できます。手動オーバーライドは現在のセッションと送信者にのみ影響し、次に北京時間 07:00 または 21:00 の切り替わりを迎えると終了します。
4. QQ からコンピューターを操作する必要が本当にある場合は、別途 `enable_computer_operations` を `true` に設定します。デフォルトは `false` です。`owner_workspace` を設定でき、空の場合はプラグインのデータディレクトリ下の作業ディレクトリを使用します。保存して再読み込みしてください。作業ディレクトリはファイルアクセスの許可リストではありません。

## 権限の範囲

| アイデンティティ | キャラクターと資料 | ローカルファイルとプログラム |
| --- | --- | --- |
| 一般メンバー | 通常の会話、許可された範囲内での資料照会、デフォルトの昼夜スケジュール | なし |
| 実際の QQ ID とフレームワーク管理者の二重検証を通過した owner | 現在のセッションでのキャラクター切り替え、状態、管理コマンド | コンピューター機能が有効で、かつそのアカウントのプライベートチャットである場合にのみ許可 |
| ローカル Web にログイン済みの管理者 | バックエンド設定、Web セッションでのキャラクター管理 | QQ owner のファイル/プログラム入口は得られません |
| ニックネーム、自称、スクリーンショット、引用、転送、またはモデルが生成した管理者アイデンティティ | 管理権限を付与しない | なし |

有効化後のファイル入口は、読み取り、ディレクトリの一覧表示、書き込み、追記をサポートします。プログラム入口は PowerShell を実行します。明示的な要求では、現在の Windows アカウントがアクセス権を持つ絶対パスを使用でき、デフォルトの作業ディレクトリに限定されません。実行には時間制限と出力制限があり、OS の権限を増やさず、UAC 昇格を引き起こしません。通常のキャラクター応答には自律的なコンピューターツールはなく、実行出力を次のコマンドとして続けて実行することもありません。

グループチャットではコンピューター操作を許可しません。初回実行時に永続的な実行レシートを保存し、同じメッセージが再送されてもプログラムを自動的に再実行しません。結果が不明確な場合は、まず新しい読み取り専用リクエストで確認してください。レシートにはコマンド、ファイル本文、プログラム出力を保存しません。利用者は引き続き、自身のプライバシー要件に従ってフレームワークのチャットログを設定してください。

互換コマンドには `/persona_status`、`/persona_reset`、`/knowledge_query`、`/电脑 帮助` があります。厳密な形式、逐語引用、キャラクター終了の場合は、末尾の `♭` を強制しません。自然な要求はモデルが理解し、権限はプログラムが検証します。モデルが「実行済み」と言っても、実際の実行結果の代わりにはなりません。

## 資料とバックアップ

公開版には 45 枚のオリジナル要約カードが付属しています。本文なし索引は Skill の `data/source-index.json` にあります。原作の完全な台詞はリポジトリに含まれていません。デプロイ担当者は、使用権がある場合に限り、`external-dialogue-memory.schema.json` に準拠したプライベートな `external_dialogue_memory.json` を、プラグインの知識索引があるデータディレクトリに配置し、再読み込み後にローカル索引を構築できます。リポジトリには入れないでください。

キャラクター、話題、会話相手、S0–S3 のネタバレ上限で検索します。デフォルトは S0/S1 です。候補資料は自動的に回答に含まれません。固定資料、チャット履歴、キャラクター状態、プライベートな実行設定は、それぞれ別にバックアップしてください。QQ ID、資格情報、私的な会話を含む実行ディレクトリを GitHub にアップロードしてはなりません。
