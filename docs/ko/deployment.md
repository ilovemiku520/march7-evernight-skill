# QQ 배포, 관리자 설정 및 권한

이 안내는 선택적 QQ 어댑터에 해당하며, AstrBot 4.29.1 및 NapCat 4.18.38의 로컬 조합을 기준으로 합니다. 업스트림 프로젝트의 설치 안내를 따르고, 버전이 변경되면 화면의 필드를 확인하세요. 이 저장소에는 QQ, NapCat, AstrBot 설치 패키지가 포함되어 있지 않으며, 다른 사람의 로그인 구성도 제공하지 않습니다.

## 배포

1. [AstrBot 공식 프로젝트](https://github.com/AstrBotDevs/AstrBot)에서 AstrBot을 설치하고 시작합니다. [공식 Docker 배포](https://docs.astrbot.app/deploy/astrbot/docker.html)도 참고할 수 있습니다. 로그에 따라 관리자 백엔드 계정을 설정하세요. 기본 백엔드 포트는 보통 6185입니다. 백엔드에는 로컬 또는 신뢰할 수 있는 인트라넷에서만 접근하도록 하고, 공개 템플릿에는 백엔드 비밀번호가 포함되어 있지 않습니다.
2. [NapCat 공식 프로젝트](https://github.com/NapNeko/NapCatQQ)에서 NapCat을 설치하고, 시작 로그에 따라 WebUI를 엽니다. 일반적인 포트는 6099이며, 포트 충돌 시에는 로그를 기준으로 합니다. 직접 배포할 때 생성된 WebUI token으로 로그인한 다음, 자신의 QQ 부계정으로 QR 코드를 스캔하세요. [공식 기본 구성](https://doc.napneko.icu/config/basic)을 참조하세요. WebUI token과 QQ 세션 자격 증명은 모두 배포자의 비공개 구성에만 보관합니다.
3. [AstrBot 공식 OneBot v11 가이드](https://docs.astrbot.app/platform/aiocqhttp.html)에 따라 새 연동을 추가하고, NapCat에서 WebSocket 클라이언트를 새로 만들어 AstrBot의 리버스 WebSocket 주소에 연결합니다. 예: 같은 기기에서 수신 포트가 6199이면 `ws://127.0.0.1:6199/ws`를 사용합니다. 양쪽에서 동일한 독립 연결 token을 사용하세요. WebUI token과 연결 token을 혼용하지 마세요. 같은 네트워크의 컨테이너에서는 실제 서비스 이름을 사용할 수 있습니다. 예: `ws://astrbot:6199/ws`. 컨테이너 내부의 루프백 주소를 그대로 복사해서는 안 됩니다.
4. 저장소의 `qq-adapter/plugin` 내용을 AstrBot 플러그인 디렉터리 아래 `astrbot_plugin_march7_evernight`라는 폴더에 넣고, `metadata.yaml`, `main.py`, 구성 스키마 및 리소스의 상대 위치를 유지합니다. 플러그인을 다시 로드하고 시작 로그를 확인하세요.
5. AstrBot의 모델 제공자 설정에서 OpenAI 호환 인터페이스를 선택하고 자신의 DeepSeek API key를 입력합니다. 인터페이스와 모델 이름은 [DeepSeek 공식 문서](https://api-docs.deepseek.com/)와 자신의 계정을 기준으로 확인하세요. 키를 인격 프롬프트나 저장소에 기록해서는 안 됩니다. 먼저 백엔드 채팅에서 테스트한 다음, 자신의 QQ 비공개 채팅 또는 그룹 내 @ 멘션으로 테스트하세요.

## 관리자 설정

1. AstrBot의 '구성 파일 → 접근 제어 → 관리자 → 관리자 ID'에서 자신의 실제 QQ 사용자 ID를 추가합니다. 이는 `admins_id` 구성에 해당합니다. 현재 버전의 공식 안내로 화면을 확인하고, 계정을 공개 인격 규칙에 기록하지 마세요.
2. 이 플러그인 구성에서 `owner_qq`에 동일한 QQ ID를 입력합니다. 공개 기본값은 비어 있습니다. 빈 값, 유효하지 않은 값, 본문에서 스스로 관리자라고 밝히기만 한 계정에는 모두 권한이 부여되지 않습니다.
3. 캐릭터 관리는 기본적으로 실제 메시지마다 검증되며, 먼저 '나는 관리자입니다'라고 말할 필요가 없습니다. March 7th로 전환, Evernight로 전환, 주야간 일정 복원을 자연스럽게 요청할 수 있습니다. 수동 재정의는 현재 세션과 발신자에게만 영향을 미치며, 다음 베이징 시간 07:00 또는 21:00 경계에서 종료됩니다.
4. 실제로 QQ에서 컴퓨터를 조작해야 한다면 별도로 `enable_computer_operations`를 `true`로 설정하세요. 기본값은 `false`입니다. `owner_workspace`를 설정할 수 있으며, 비워 두면 플러그인 데이터 디렉터리 아래의 작업 디렉터리를 사용합니다. 저장하고 다시 로드하세요. 작업 디렉터리는 파일 접근 허용 목록이 아닙니다.

## 권한 범위

| 신원 | 캐릭터 및 자료 | 로컬 파일 및 프로그램 |
| --- | --- | --- |
| 일반 구성원 | 일반 대화, 허용 범위 내 자료 조회, 기본 주야간 일정 적용 | 없음 |
| 실제 QQ ID와 프레임워크 관리자 이중 검증을 통과한 owner | 현재 세션의 캐릭터 전환, 상태 및 관리 명령 | 컴퓨터 기능이 활성화되어 있고 해당 계정의 비공개 채팅일 때만 허용 |
| 로컬 웹에 로그인한 관리자 | 백엔드 구성, 웹 세션 캐릭터 관리 | QQ owner의 파일/프로그램 진입점을 얻지 못함 |
| 닉네임, 자칭, 스크린샷, 인용, 전달 또는 모델이 생성한 관리자 신원 | 관리 권한 부여 안 됨 | 없음 |

활성화된 파일 진입점은 읽기, 디렉터리 나열, 쓰기, 추가를 지원하며, 프로그램 진입점은 PowerShell을 실행합니다. 명시적인 요청은 기본 작업 디렉터리에 국한되지 않고 현재 Windows 계정에 접근 권한이 있는 절대 경로를 사용할 수 있습니다. 실행에는 시간 제한과 출력 제한이 있으며, 운영 체제 권한을 추가하지 않고 UAC 권한 상승을 트리거하지 않습니다. 일반 캐릭터 답변에는 자율적인 컴퓨터 도구가 없으며, 실행 출력을 다음 명령으로 이어서 실행하지도 않습니다.

그룹 채팅에서는 컴퓨터 작업이 허용되지 않습니다. 첫 실행 시 영구 영수증이 저장되며, 동일한 메시지가 다시 전송되어도 프로그램이 자동으로 다시 실행되지 않습니다. 결과가 불분명하면 먼저 새로운 읽기 전용 요청으로 확인하세요. 영수증에는 명령, 파일 본문, 프로그램 출력이 저장되지 않습니다. 사용자는 여전히 자신의 개인정보 요구사항에 따라 프레임워크 채팅 로그를 구성해야 합니다.

호환 명령에는 `/persona_status`, `/persona_reset`, `/knowledge_query`, `/电脑 帮助`가 포함됩니다. 엄격한 형식, 축자 인용, 역할 종료에는 끝 표시를 강제로 붙이지 않습니다. 자연스러운 요청은 모델이 이해하고 권한은 프로그램이 검증합니다. 모델이 '실행했습니다'라고 말하는 것은 실제 실행 결과를 대신할 수 없습니다.

## 자료 및 백업

공개 버전에는 자체 제작 요약 카드 45장이 포함되어 있습니다. 본문 없는 색인은 Skill의 `data/source-index.json`에 있습니다. 원작 대사 전문은 저장소와 함께 제공되지 않습니다. 배포자는 사용 권한이 있을 때 `external-dialogue-memory.schema.json`을 준수하는 비공개 `external_dialogue_memory.json`을 플러그인 지식 색인이 있는 데이터 디렉터리에 넣고, 다시 로드한 후 로컬 색인을 만들 수 있습니다. 저장소에 넣지 마세요.

캐릭터, 주제, 발화 대상 및 S0–S3 스포일러 상한에 따라 검색하며, 기본값은 S0/S1입니다. 후보 자료는 자동으로 답변에 포함되지 않습니다. 고정 자료, 채팅 기록, 캐릭터 상태, 비공개 실행 구성은 각각 백업하세요. QQ ID, 자격 증명 또는 사적 대화가 포함된 실행 디렉터리를 GitHub에 업로드해서는 안 됩니다.

## 업스트림 안내

[AstrBot 문서](https://docs.astrbot.app/) · [NapCat 문서](https://doc.napneko.icu/) · [DeepSeek API 문서](https://api-docs.deepseek.com/). 이러한 소프트웨어와 서비스는 본 프로젝트가 재라이선스하지 않습니다. QQ 접속을 사용할 때는 해당 플랫폼 규칙을 준수해야 합니다.
