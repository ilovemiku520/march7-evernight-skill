# Public adapter validation

Validated on 2026-10-19 in a local Windows Python environment. All **323 offline tests passed**.

| Test file | Passed |
| --- | ---: |
| `test_adapter.py` | 92 |
| `test_engine.py` | 205 |
| `test_normalization_exit.py` | 7 |
| `test_owner_operations.py` | 19 |

The suite covers transactional delivery and rollback, scheduled and manual persona changes, role identity, strict formatting, role exit, cross-speaker and spoiler isolation, external-memory validation, natural management intent handling, persistent duplicate prevention, and bounded host-operation results. Public-release checks add empty-owner denial, computer access disabled by default, separation of WebChat administration from QQ identity, configuration type validation, configurable working directories, and distinct explicit `A00` / `A01` knowledge cards.

The bundled public knowledge loaded successfully as **45 original summary cards**. No summary is labeled as an exact canonical quotation anchor. A topical umbrella query returns the appropriate public summary, while automatic canonical-quotation injection remains empty until a deployer supplies locally authorized, attributed records.

The public adapter's source, resources, configuration schema, and tests were checked for the original private account identifier, author-specific absolute paths, and literal credential patterns; none were found. Account IDs in tests are synthetic fixtures. Test-only error labels and the deliberately invalid URL-credential fixture are synthetic validation data. The framework's `_api_key_allow_admin_role` field is a runtime authorization flag, not a bundled API key; it remains intact so authentication is not weakened. No provider credential, QQ login cache, conversation database, runtime receipt database, private corpus, or original full dialogue export is included. Compiled Python caches were removed because they can embed build-machine filenames.

These are offline contract and data-loading checks. They do not send QQ messages, call model APIs, or certify a new live QQ connection. The separately configured AstrBot and QQ adapter must still be tested by the deployer on their own account.
